# 项目级 S2 条件结果持久化实施与验收报告

日期：2026-11-13

## 实施内容

- 新增 PostgreSQL 表 `s2_condition_results`，每行对应一个 S2 药物扰动条件，关联项目 ID 和 S2 AnalysisRun ID。
- 条件键保留 `cell_id`、`pert_type`、`time` 和 `dose`。结果 JSON 保留原 `drug_condition_summary.csv` 行的药名、signature 数、WTCS 汇总、质量指标和条件内排名。
- 唯一约束以 AnalysisRun、条件键和 LINCS perturbagen ID 组成，重复导入保持幂等。
- `/projects/{project_id}/s2/conditions` 对新导入运行从数据库分页读取。已登记但尚未回填的历史运行仍通过其哈希核验后的 CSV 返回，兼容旧数据。
- 前端 S2 页面现可选择项目内完成的 S1 并启动新的 S2 运行；新运行结果经同一导入门禁写入该表。
- 不会将不同剂量或时间混成单一药物分数，也不会从条件级结果推断统一的候选药物总排名。跨条件汇总需要另行确定并记录规则。

## 数据库与验证

- Alembic 迁移 `1a9c43d820ef` 已在本机开发 PostgreSQL 从 `4d2c7ea19a6b` 升级执行。迁移仅新增条件结果表、项目/运行外键、唯一约束和索引，不改动历史 S1/S2 科研文件。
- 新增隔离数据库自动测试覆盖两剂量分别保留、非整数平均排名保留、项目条件查询及重复导入幂等。初次测试发现测试清单漏写 S1 SHA-256，修复夹具后测试通过；没有放宽生产导入的哈希门禁。
- 本轮最终后端测试与 S2 工程测试结果见平台主报告。测试数据仅用于软件验证。
